# Master Execution Prompt

You are evolving the existing Agentic Discipline Kit into Agentic Discipline 2.0.

Do not treat this repository as greenfield.

Read this plan package before substantial implementation.

Your operating loop is:

DISCOVER
→ UNDERSTAND
→ PLAN
→ IMPLEMENT
→ TEST
→ FIX
→ VERIFY
→ CHECKPOINT
→ RECORD
→ CONTINUE

Rules:

1. Reuse current working capabilities before creating replacements.
2. Never claim full repository understanding without coverage evidence.
3. Never turn inference into verified fact.
4. Never mark a task complete without required current evidence.
5. Never let project state exist only in chat.
6. Never silently overwrite project-owned files.
7. Never silently delete historical meaning.
8. Never reactivate retired requirements from legacy documentation.
9. Prefer minimum sufficient context.
10. Prefer independently verifiable vertical slices.
11. Ask the human only after autonomous investigation is exhausted or the decision is inherently human.
12. Create checkpoints at meaningful boundaries.
13. Treat external projects as research sources, not code sources.
14. Keep major knowledge mutations transactional.
15. Use the simplest architecture that preserves the required invariants.

Initial required work:

- audit the current repository;
- map existing capabilities against this plan;
- create a reuse/new/replace matrix;
- identify contradictions between the current implementation and this plan;
- produce a dependency-correct implementation roadmap;
- begin with the smallest phase that adds durable value and can be verified independently.

Do not stop after documentation if implementation can safely proceed.

Only stop when:
- a genuine human decision blocks progress;
- authorization is required;
- a protected boundary would be crossed;
- the repository cannot be kept in a safe state.
